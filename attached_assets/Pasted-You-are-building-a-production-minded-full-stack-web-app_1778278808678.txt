You are building a production-minded full-stack web app called “Geenbank Hub”.

The app is a financing application hub for prospects who entered through Geenbank’s website but were disqualified from Geenbank’s core ICP. Instead of rejecting these leads, the hub helps them complete a structured financing file, upload and validate documents, run AI-based financial analysis through existing callable skills, and prepare qualified cases for a loan officer and eventually partner financiers.

UI language: Dutch, Netherlands Dutch.
Tone: clear, entrepreneurial, reassuring, direct, practical.
Prospect-side copy must avoid bank jargon.
Loan-officer/admin-side copy may use financier and credit language.

Important architectural rule:
Do not rebuild the financial AI skills from scratch. Treat these as existing callable skill modules that may be available to the Replit agent, backend, standard Replit capabilities, project-added skills, or custom skills placed inside this Replit project:

- credit-product-advisor
- financing-need-assessor
- financing-product-advisor-dual-view
- geenbank-kredietworkflow
- moneycare-kredietmemorandum-fabriek

Build the app so these skills are called server-side through a clear adapter/service layer. If the exact invocation interface is unknown, create clean placeholder adapters with typed inputs and outputs, clear TODOs, realistic mock responses for local development, and logging. The frontend flow must not need to change when the real skill calls are connected later.

Stack selection:
Choose the most suitable stack for this project. Prefer a maintainable full-stack web app with:
- secure authentication
- role-based access control
- database persistence
- file/document uploads
- background AI processing jobs
- email notifications
- API integrations with Pipedrive and SendGrid

Use environment variables for all secrets. Do not expose API keys client-side. Prepare the app so it can later be connected to a custom domain.

Core product outcome:
The app must convert disqualified Geenbank leads into structured, validated financing dossiers that can either:
- help the entrepreneur understand and improve their financing position, or
- be reviewed by a loan officer and submitted to selected partner financiers.

Primary users:
1. Prospect / entrepreneur
A business owner who needs financing but does not match Geenbank’s core ICP. The entrepreneur must be guided through a motivating, simple, clear financing intake experience.

2. Loan officer / admin
An internal Geenbank user who reviews only qualified, sufficiently complete, AI-prevalidated dossiers and decides whether the file is good enough to send to partner financiers.

Non-negotiable product standard:
Do not build a plain CRUD dashboard first and improve design later. The first build must already feel like a premium, innovative financing experience, not a generic form portal, CRM skin, or bank backoffice.

The app must include from the first build:
- strong visual identity direction
- clear information hierarchy
- polished layouts
- premium UI components
- smooth step-by-step user flow
- excellent empty, loading, blocked, success, and error states
- motivational microcopy
- visual progress indicators
- clear next-best-action guidance
- responsive layouts
- distinctive Geenbank feel

Every screen must answer:
1. What is happening?
2. Why does this matter for the user’s financing goal?
3. What does the user need to do next?
4. What happens after this step?

If a feature technically works but the flow feels confusing, dry, generic, or visually weak, it is not accepted.

Main prospect workflow:
1. A lead is disqualified on the Geenbank website.
2. Zapier places the lead/deal in Pipedrive in pipeline “Geenbank | Banking Hub”, first stage.
3. The app receives or fetches deal data through the Pipedrive API.
4. The app creates a prospect account using the prospect’s email and a system-generated temporary password.
5. The app sends login details through SendGrid.
6. The prospect logs into a personal financing page.
7. The prospect completes the application:
   - company details
   - financing need
   - purpose of financing
   - requested amount
   - existing financing
   - revenue/cost/profit information if available
   - explanation of business situation
   - required document uploads
8. The app clearly shows which documents are needed and why they matter.
9. The AI pre-validation agent checks:
   - document completeness
   - minimum document quality
   - whether documents match the company/application
   - whether essential figures can be extracted
   - whether contradictory or obviously invalid data exists
10. If the file is incomplete or minimally incorrect:
   - block full AI evaluation
   - show a clear explanation to the prospect
   - show exactly what must be fixed or uploaded
   - allow re-upload and re-validation
11. If the file passes completeness and minimum correctness:
   - run financial AI analysis through the available skill modules
   - generate an entrepreneur-facing report
12. The entrepreneur sees:
   - current application status
   - strong points in the financing file
   - weak/improvable points
   - practical action points
   - what Geenbank or partner financiers are likely to need
13. If the AI verdict is positive enough, the entrepreneur can click “Indienen bij Geenbank”.
14. After submission, the entrepreneur can keep following the status.

Main loan officer/admin workflow:
1. Loan officer logs in through a separate admin login.
2. Loan officer sees a dashboard with:
   - new submitted dossiers
   - dossier quality categories
   - status overview
   - pipeline stages aligned with Pipedrive
   - where prospects get stuck
   - daily intake overview
3. Only dossiers that pass all three gates may appear for loan officer review:
   - document completeness is sufficient
   - minimum document correctness is sufficient
   - minimum AI dossier score is reached
4. The loan officer opens a dossier and sees:
   - company/application summary
   - entrepreneur-facing report
   - financier-facing credit report
   - AI verdict
   - confidence score
   - reasons for the verdict
   - document list
   - missing or recommended additional documents
   - blocking conditions
   - non-blocking conditions
   - underlying uploaded documents
5. The loan officer can:
   - approve for partner submission
   - reject
   - request additional documents from the entrepreneur
6. If additional documents are requested:
   - the app sends an email to the entrepreneur
   - the prospect dashboard shows requested items
   - the status updates
7. If approved:
   - loan officer selects one or more partner financiers
   - the agent prepares a complete credit memorandum in the fixed format
   - the app attaches relevant documents
   - the loan officer reviews the final package
   - the loan officer clicks “Aanbieden”
   - the app sends the dossier package to selected partners or creates a safe mock-send preview
8. Loan officer/admin can manage partner financiers:
   - add partner
   - edit partner
   - pause partner
   - set partner product preferences
   - view performance metrics

Required AI workflow:
Build the AI workflow as a staged backend pipeline:

Stage 1 — Intake normalization
Normalize prospect input into one internal case object.

Stage 2 — Document completeness check
Check whether required documents are present based on financing type, company type, and available information.

Stage 3 — Minimum correctness check
Check whether documents are readable, relevant, not empty, likely belong to the applicant, and contain usable financial data.

Stage 4 — Data extraction and consolidation
Extract and consolidate:
- annual figures
- interim figures
- bank transactions
- forecasts
- debtor/creditor information if present
- financing need
- cash flow capacity
- collateral/security information
- repayment capacity indicators

Stage 5 — Financial analysis
Call the available financial skills through the backend adapter layer.

Stage 6 — Scoring and gating
Generate:
- completeness score
- correctness score
- financial viability score
- confidence score
- blocking conditions
- non-blocking conditions
- final AI verdict

Stage 7 — Reports
Generate two report views from the same underlying analysis:
1. entrepreneur report: understandable, practical, motivating
2. financier report: structured, credit-oriented, suitable for loan officer review

Stage 8 — Partner submission package
Generate:
- final credit memorandum
- required attachments list
- partner-specific submission notes
- email/package draft for selected partners

Blocking conditions:
The app must block full AI evaluation and loan officer submission when:
- required documents are missing
- files are unreadable or invalid
- core company identity cannot be matched
- essential financial data cannot be extracted
- the case lacks enough information to produce a reliable assessment
- the AI confidence score is below the defined minimum
- the overall dossier score is below the defined minimum

Non-blocking conditions:
The app may allow progression but must flag:
- missing optional supporting documents
- limited forecast substantiation
- weak explanation of financing purpose
- incomplete collateral information
- limited management information
- older annual figures
- unclear repayment assumptions
