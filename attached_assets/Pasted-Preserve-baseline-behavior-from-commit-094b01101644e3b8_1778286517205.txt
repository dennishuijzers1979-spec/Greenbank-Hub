Task: Add AI skill invocation observability to Geenbank Hub.

Problem:
The project owner has useful skills in ChatGPT/OpenAI/Replit context, but it is currently unclear whether the Geenbank Hub backend calls real skills, calls OpenAI/Anthropic, calls HTTP endpoints, or only uses deterministic mocks.

Goal:
Make AI skill usage explicit, auditable, and visible in admin/loan officer tooling before wiring real skills.

1. Add central AI skill runtime config

Create a central server-side AI runtime config/helper that determines:
- selected provider
- whether real invocation is possible
- whether mock mode is used
- why mock mode is used
- configured model, endpoint, or assistant id
- missing environment variables

Support provider-neutral config such as:

AI_SKILL_PROVIDER=mock|openai|http|replit
OPENAI_API_KEY
OPENAI_MODEL
ANTHROPIC_API_KEY
ANTHROPIC_MODEL
SKILL_CREDIT_PRODUCT_ADVISOR_ENDPOINT
SKILL_FINANCING_NEED_ASSESSOR_ENDPOINT
SKILL_FINANCING_PRODUCT_ADVISOR_DUAL_VIEW_ENDPOINT
SKILL_GEENBANK_KREDIETWORKFLOW_ENDPOINT
SKILL_MONEYCARE_KREDIETMEMORANDUM_ENDPOINT
SKILL_CREDIT_PRODUCT_ADVISOR_ASSISTANT_ID
SKILL_FINANCING_NEED_ASSESSOR_ASSISTANT_ID
SKILL_FINANCING_PRODUCT_ADVISOR_DUAL_VIEW_ASSISTANT_ID
SKILL_GEENBANK_KREDIETWORKFLOW_ASSISTANT_ID
SKILL_MONEYCARE_KREDIETMEMORANDUM_ASSISTANT_ID

Do not hard-code Anthropic as the only live provider.
Default safely to mock mode when no real provider is configured.

2. Add consistent invocation metadata

Every skill adapter call must produce consistent metadata:
- skillName
- provider
- usedMockMode
- model
- endpoint or assistant id, without secrets
- startedAt
- completedAt
- durationMs
- inputSummary
- outputSummary
- errorMessage
- fallbackReason

Do not store API keys or secrets.

3. Store metadata with analysis runs

Attach the per-skill invocation metadata to AIAnalysisRun or a related structured field.
If the existing schema already has a suitable JSON field, use it.
If not, add the smallest compatible schema change.

Every analysis run should show:
- which skill adapters ran
- which were mock vs real
- why a mock fallback was used
- whether any adapter failed and recovered
